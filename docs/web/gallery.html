Scope, evidence and limitations

The real frontend talks to local Nhost with fictional, private fixture data and a new account per layout. No production sessions, public-data writes or database resets are used. Fonts are pinned locally for capture. Application, Auth and server clocks remain real; history is relative to the manifest's fixture date.

This initial catalog covers all 14 web section roots and representative strength logging, nutrition logging, journal CRUD and appearance workflows. It is not exhaustive CRUD, state, tablet or browser compatibility coverage. Progress Overview and native Health/Watch actions are not implemented on the web.

“Apple Health” markers are fictional fixture notes demonstrating read-only source presentation, not evidence of an import. Recorded backend checks do not replace the backend permission/integrity suite. Offline validation verifies retained evidence and file integrity; it does not rerun browser workflows.
